### BUG-1 — Dialog error ไม่แสดงจนกว่าผู้ใช้จะคลิก/กด Esc เมื่อ request ที่ล้มเป็น `rxResource` ของหน้า
- **Expected (ERR-03 + TC-ERR-002/3/4 s1)**: เมื่อ API ล้ม (40102 / status 0 / 5000x) dialog ขึ้นทันที
- **Actual**: หน้า Home (`/home`) และ Report (`/report`) ที่โหลดข้อมูลผ่าน `rxResource` — เมื่อ request ล้ม หน้าไม่มี dialog และไม่มีข้อความ error ใดๆ (Home แสดง "Welcome back," ว่าง) จนกว่าผู้ใช้คลิกที่ใดก็ได้หรือกด Esc 1 ครั้ง (ตรวจ 30 วินาทีโดยไม่โต้ตอบ = ไม่ขึ้น; คลิก/Esc = ขึ้น; Tab/พิมพ์ตัวอักษร/เลื่อน/ปรับขนาดจอ = ไม่ขึ้น) ขณะที่ request ที่ผู้เรียกจัดการ error เอง (เช่น login) dialog ขึ้นทันที ทั้ง desktop/phone
- **Console**: `ERROR … API error: network` พร้อม stack `at … computation` ตอนโหลดหน้า — สอดคล้องสมมติฐาน (ยังไม่ยืนยัน ไม่ได้แก้โค้ด) ว่า template อ่าน `systems.value()` ของ resource ขณะอยู่ในสถานะ error → throw ระหว่าง change detection ทำให้ `<u-http-error-dialogs>` ยังไม่ถูก render จนมี event ถัดไป (โค้ด: `home-page.html` อ่าน `systems.value()` ตรงๆ)
- **Reproduce**: build production, จำลอง `GET /v1/Home/get-userSystems` ตอบ 40102 (หรือ abort) ด้วย `docs/qa/results/2026-11-26-playwright/prod8.mjs` (หรือ `prod11.mjs`), login แล้วรอ — เทียบกับ `prod10.mjs` (ล้มที่ login → dialog ขึ้นทันที)
- **ความรุนแรง**: Medium — ผู้ใช้เห็นหน้าว่างโดยไม่รู้สาเหตุจนกว่าจะคลิก; เกิดเฉพาะเมื่อ API ล้ม
- **ข้อเสนอ: issue ใหม่ (ไม่ตีกลับ ERR-03)** — dialog ของ ERR-03 ทำงานถูกเมื่อผู้เรียกจัดการ error; ต้นเหตุอยู่ที่หน้าที่อ่าน resource ตอน error (ขอบเขตของ UAM-HOM-02 / UAM-ERR-05 / UAM-RPT-02 ที่ยังเป็น todo) แนะนำเพิ่มเกณฑ์ "ไม่ throw เมื่อ resource error และ dialog ขึ้นทันที" ใน HOM-02/RPT-02/ERR-05 หรือเปิด bug ข้ามหน้าเดียว (Senior ตัดสินว่าแก้ที่หน้าหรือที่ dialog host) — ทางเลือกที่สอง: ตีกลับ ERR-03 หากต้องการให้ dialog host ทนต่อ error ของหน้าทุกหน้า
