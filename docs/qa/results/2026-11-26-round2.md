## Bug / ข้อสังเกต

### BUG-2 (ใหม่) — เมนู Logout บน topbar ไม่ล้าง session ที่คงไว้ (regression จาก UAM-AUT-03)
- **Expected**: กด Logout แล้วผู้ใช้ออกจากระบบจริง — เปิด `/home` หรือรีโหลดหลังจากนั้นต้องกลับ `/login`
- **Actual**: กด Logout → ไป `/login` แต่ `sessionStorage['uam.session']` **ยังอยู่** และไม่มี request `POST /v1/auth/logout`; เปิด `/home` หรือ `/setting/users-setting` ตรงๆ (หรือรีโหลดแล้วกลับไป URL) ใน tab เดิม → **เข้าได้เต็ม** เห็นการ์ดของผู้ใช้เดิม (ทดสอบ demo และ production+mock, desktop+phone)
- **สาเหตุที่เห็นจากโค้ด (ยังไม่ยืนยันด้วยการแก้)**: `src/app/layout/shell/shell.html` ลิงก์ Logout เป็น `<a href="/login" (click)="onNavigate()">` (โหลดหน้าใหม่ ไม่เรียก logout/ไม่ clear session) — ก่อน AUT-03 session อยู่ในหน่วยความจำจึง "หาย" เองตอนโหลดหน้า; AUT-03 ทำให้คงข้ามการโหลด จึงกลายเป็น logout ที่ไม่ได้ผล (ผ่านเฉพาะ Decline ที่หน้า consent ซึ่งล้าง session ถูกต้อง)
- **Reproduce**: `docs/qa/results/2026-11-26-round2-playwright/demo-auth.mjs` (หรือ `logout.mjs`): login `admin.user` → เมนูผู้ใช้ → Logout → เปิด `/home`
- **ความรุนแรง**: High (ความปลอดภัย/ความคาดหวังของผู้ใช้ — เครื่องใช้ร่วมกัน; session ค้างจนปิดแท็บ). ไม่มี TC ครอบ (TC-RBAC-001 s? ตรวจแค่ว่าไป `/login`)
- **ข้อเสนอ: ตีกลับ UAM-AUT-03** — เป็น regression ของ PR ที่เพิ่ง merge (การคง session ต้องมาพร้อมการล้างเมื่อ Logout; AC "การกู้ session" ของ item); แนวแก้ที่เสนอให้ dev พิจารณา: Logout เรียก `auth/logout` + ล้าง session แล้วไป `/login` ด้วย router; และเพิ่ม TC (เช่น TC-AUT-010 "Logout แล้วเปิด /home ต้องไป /login"). ทางเลือก: ถ้า PM ต้องการปิด AUT-03 เป็น done เพราะ TC ของ item ผ่านครบ ให้เปิด issue ใหม่ P0/P1 เรื่อง Logout แทน
